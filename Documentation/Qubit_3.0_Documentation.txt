#imported it in main.py and declared tool_mapping and tools

    tools-List of tools exposed to Gemini.
    So Gemini knows what actions are available.
    Example:
    "Open App"
    "Close App"
    "Get Battery Status"

    Without tools:
    Gemini doesn't know these functions exist.


    tool_mapping-Dictionary that connects tool names to actual Python functions.
    Example:
    "open_app"
        ↓
    open_app()

    "close_app"
        ↓
    close_app()

    When Gemini says:
    "I want to call open_app"
    Python must know which function to execute.

    Without tool_mapping:
    Gemini knows the tool exists,
    but Python doesn't know where the code is.

         ↓
   GeminiLive(...) #passed through this constructor to the gemini_live.py
         ↓
   tool_mapping parameter 
         ↓
   self.tool_mapping #declaration in gemini_live.py automatically happens


#Process Control Journey!!!

   #Started with separate functions
      open_brave()
      open_vscode()
      open_terminal()

      Problem:
      - Repetitive code
      - Need new function for every app

   #Created Generic App System
      Apps = {
         "brave": {...},
         "vscode": {...},
         ...
      }
      Functions:
      - open_app(app)
      - close_app(app)

      Benefit:
      - One function works for all apps

   #Implemented Closing using pkill
      pkill -f process_name

      Problem:
      - Closed every matching process
      - Closing VS Code also killed Nexus

   #Switched to PID Tracking
      process = subprocess.Popen(...)
      opened_apps[app] = process

      Close using:
      process.terminate()

      Benefit:
      - Closes only apps opened by Nexus

   #Added Process Detection
      is_running()
      Uses:
      psutil.process_iter()

      Added:
      "process" field in Apps dictionary

      Example:
      "vscode": {
         "process": "/usr/share/code/code"
      }

      Benefit:
      - Prevents opening duplicate apps

   #Added New Window Support
      Functions:
      - open_new_app()
      - close_new_app()

      Examples:
      Open new VS Code
      Open new Brave
      Open new Notes

   #Discovered Launcher PID Problem

      subprocess.Popen()
      returns launcher PID
      Real application often starts in another PID

      Launcher PID may die
      Not reliable for VS Code, Brave, Chrome


   #Implemented Process Discovery

      Take PID snapshot before launch
      Launch app
      Take PID snapshot after launch
      Find newly created PIDs
      Store actual application PIDs
               ||
      before = running PIDs
      launch app
      after = running PIDs
      new_pids = after - before

      Benefit:
      - Notes/Kate open and close works 
      Cons:
      - Captures helper processes too
      - Browser issues


   #Brave Special Case

      Brave shows:
      "Opening in existing browser session"

      Meaning:
      - New window uses existing browser process
      - No separate browser PID created

      Result:
      - PID tracking cannot close individual Brave windows
